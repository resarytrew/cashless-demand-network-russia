# Техническое приложение

## Назначение документа

Этот документ дополняет основную методологию и фиксирует точную техническую реализацию исследования. Здесь собраны параметры, формулы, определения метрик, правила сопоставления разбиений, протоколы проверок устойчивости, детали внешней валидации, алгоритмические benchmark и процедуры воспроизводимости.

Основной документ с объяснением логики исследования находится в [`METHODOLOGY.md`](METHODOLOGY.md). Здесь акцент сделан на точных вычислительных определениях.

Сохранённые YAML конфигурации, исходный код и первичные таблицы имеют приоритет над текстовым пересказом, если между ними обнаружится расхождение.

## 2. Точное построение признаков

### 2.1. Композиционный блок

Для каждого муниципалитета в каждом месяце используются пять опубликованных категорий:

1. продовольствие;
2. здоровье;
3. общественное питание;
4. маркетплейсы;
5. транспорт.

Техническая шестая часть вычисляется как:

```text
Other = Total - сумма пяти опубликованных категорий
```

`Other` не интерпретируется как самостоятельная отрасль или содержательная категория.

Все шесть частей должны быть строго положительными. При наличии неположительной части CLR преобразование не выполняется.

Для каждой части:

```text
p_j = x_j / Total
```

После этого применяется центрированное логарифмическое отношение:

```text
CLR_j = ln(p_j) - mean_h[ln(p_h)]
```

Реализация находится в [`../src/sbernet/features.py`](../src/sbernet/features.py).

### 2.2. Блок общего уровня

Используется:

```text
l_i = ln(Total_i)
```

Внутри каждого месяца выполняется устойчивая стандартизация:

```text
z_i = (l_i - median(l)) / (1,4826 × MAD(l))
```

Если `MAD = 0`, расчёт прекращается.

### 2.3. Нормировка блоков

Композиционный блок и блок уровня отдельно делятся на собственное медианное попарное евклидово расстояние внутри месяца.

Это предотвращает автоматическое доминирование одного блока только из-за численного масштаба координат.

### 2.4. Итоговая геометрия

Координаты композиционного блока умножаются на `sqrt(0,70)`, координаты уровня на `sqrt(0,30)`.

Поэтому квадрат итогового евклидова расстояния эквивалентен:

```text
d² = 0,70 × d²_structure + 0,30 × d²_level
```

## 3. Построение месячного графа

Для каждого месяца строится отдельный неориентированный взвешенный граф.

### 3.1. Поиск соседей

Для каждого узла находятся `k + 1` ближайших точек, включая сам узел. После удаления самого узла остаются 20 соседей.

### 3.2. Взаимное соседство

Ребро между `i` и `j` существует только в том случае, если:

```text
j входит в 20 ближайших соседей i
и
i входит в 20 ближайших соседей j
```

Это правило обозначается `mutual-kNN`.

### 3.3. Адаптивный вес

Для каждого узла `sigma_i` равно расстоянию до двадцатого ближайшего соседа.

Вес ребра:

```text
w_ij = exp[-d_ij² / (sigma_i × sigma_j + 1e-12)]
```

Такое ядро адаптируется к локальной плотности пространства признаков.

### 3.4. Изолированные узлы

Для статического декабрьского графа включён `static_isolate_fallback`. Если узел остаётся изолированным, он соединяется со своим ближайшим соседом.

Для месячных слоёв временной модели `temporal_isolate_fallback` выключен.

Реализация находится в [`../src/sbernet/graph.py`](../src/sbernet/graph.py).

## 4. Расширенная временная сеть

Все 24 месячных графа объединяются в единую supra сеть.

Каждый узел имеет вид:

```text
(муниципалитет, месяц)
```

Общее число узлов:

```text
1 904 × 24 = 45 696
```

Все внутримесячные рёбра переносятся в соответствующий временной слой без изменения веса.

Один и тот же муниципалитет связывается с самим собой в соседних месяцах.

Вес такого ребра:

```text
w_temporal = omega × median(w_intralayer)
```

где `median(w_intralayer)` представляет собой глобальную медиану весов всех внутримесячных рёбер в supra сети.

В опорной модели:

```text
omega = 2
```

Реализация находится в [`../src/sbernet/temporal.py`](../src/sbernet/temporal.py).

## 5. Целевая функция кластеризации

Для всей расширенной сети оптимизируется обычная взвешенная модульность:

```text
Q_gamma = (1 / 2m) × sum_u,v [
    W_uv - gamma × s_u × s_v / (2m)
] × 1(c_u = c_v)

s_u = sum_v W_uv
m = (1/2) × sum_u,v W_uv
```

Здесь:

* `W` представляет собой взвешенную матрицу связей;
* `s_u` представляет собой силу узла;
* `m` представляет собой суммарный вес неориентированных рёбер;
* `gamma` соответствует `resolution`;
* в опорной модели `gamma = 0,5`.

Сила узла включает как внутримесячные, так и межмесячные рёбра.

Ожидаемая связанность рассчитывается по всей supra сети. Поэтому модель не является классической multislice modularity с отдельной нулевой моделью для каждого слоя.

Оптимизируемое `Q` при `gamma = 0,5` нельзя смешивать с отчётным Newman Girvan `Q`, который в ICVI v2 рассчитывается при `resolution = 1`, а также с TurboMQ.

Алгоритм кластеризации реализован в [`../src/sbernet/clustering.py`](../src/sbernet/clustering.py).

## 7. Сопоставление альтернативных разбиений

Пусть `R` представляет собой исходную группу, а `S` представляет собой группу альтернативного разбиения с максимальным пересечением с `R`.

Используются три разные меры.

### 7.1. Сохранение участников

```text
retention = |R ∩ S| / |R|
```

Показывает, какая доля исходной группы сохранилась вместе.

### 7.2. Точность группы назначения

```text
destination precision = |R ∩ S| / |S|
```

Показывает, какую долю новой группы составляют участники исходной группы.

### 7.3. Коэффициент Жаккара

```text
destination Jaccard = |R ∩ S| / |R ∪ S|
```

Он одновременно учитывает потерю исходных участников и поглощение новых.

При равном пересечении выбирается группа назначения с меньшим числовым идентификатором.

Несколько исходных групп могут иметь одну и ту же группу назначения.

Высокий `retention` при низком `destination precision` означает сохранение ядра внутри более крупной группы. Такой результат не считается сохранением точной границы.

## 8. Канонический perturbation v2

Проверка возмущениями использует 50 запусков, seeds от 0 до 49.

Конфигурация находится в [`../configs/perturbation_v2.yaml`](../configs/perturbation_v2.yaml).

### 8.1. Возмущение структуры графа

Для внутримесячных рёбер применяется:

```text
вероятность удаления = 0,05
```

Сохранённые веса умножаются на логнормальный множитель:

```text
w* = w × exp(epsilon)
epsilon ~ N(0, 0,02²)
```

Временные рёбра не изменяются.

### 8.2. Случайность алгоритма

Seed Лувена равен номеру perturbation запуска.

### 8.3. Канонический порядок

Перед применением случайности рёбра сортируются по идентификаторам концов. Это устраняет зависимость результата от порядка вставки рёбер в объект графа.

### 8.4. Reproduction gate

До запуска 50 повторов seed 0 пересчитывается:

1. дважды в одном процессе;
2. в отдельном свежем Python процессе;
3. после обратного порядка вставки узлов и рёбер.

Сравниваются точные хэши:

* канонического списка рёбер;
* маски сохранения;
* массива jitter;
* внутримесячных рёбер после возмущения;
* временных рёбер;
* финальной supra сети.

Сравнение выполняется без численного допуска.

Исторический пилот `n=5` не используется как текущая количественная доказательная база.

## 9. Stability Atlas

Текущая конфигурация Atlas имеет версию `2.2.1`.

Настройки находятся в [`../configs/stability_atlas_v2_2_1.yaml`](../configs/stability_atlas_v2_2_1.yaml).

### 9.1. Четыре семейства

Atlas использует четыре семейства проверок:

1. `perturbation`, 50 запусков;
2. `alpha`, 2 альтернативы весов;
3. `gamma`, 3 альтернативы `resolution`;
4. `algorithm`, 1 альтернативный алгоритм.

### 9.2. Матрица совместного попадания

Для семейства `f`:

```text
C_f(i,j) = (1 / n_f) × sum_r 1(c_i,r = c_j,r)
```

После этого семейства усредняются с равными весами:

```text
C(i,j) = 0,25 × sum_f C_f(i,j)
```

Поэтому 50 perturbation запусков не получают в 50 раз больший вес, чем одно алгоритмическое сравнение.

### 9.3. Близость к профилю

Для муниципалитета `i` и reference профиля `g`:

```text
a(i,g) = среднее C(i,j) по j из reference g, j != i
```

Затем:

```text
p(i,g) = a(i,g) / sum_h a(i,h)
```

`p(i,g)` представляет собой нормированную долю близости. Это не статистическая вероятность.

### 9.4. Разрыв и энтропия

```text
margin(i) = p(i,первый) - p(i,второй)
```

```text
entropy(i) =
-sum_g p(i,g) ln p(i,g) / ln(7)
```

Высокая энтропия означает распределённую близость к нескольким профилям.

Малый `margin` означает слабое преимущество ведущего профиля.

При нулевой суммарной близости назначается `unresolved`.

### 9.5. Категории устойчивости

Категория устойчивости задаётся по perturbation диагностике.

| Категория | Правило |
|---|---|
| `stable_core` | `peer >= 0,85`, `precision >= 0,75`, `Jaccard >= 0,65` |
| `expansive_core` | `peer >= 0,85`, но `precision < 0,75` или `Jaccard < 0,65` |
| `transition` | `peer < 0,75` и `Jaccard < 0,50` |
| `unresolved` | остальные случаи и технические микропрофили |

`peer` представляет собой агрегированное совместное попадание с участниками исходного профиля.

`expansive_core` означает устойчивое окружение при недостаточно определённой внешней границе.

### 9.6. Проверка с исключением одного семейства

Atlas пересчитывается четыре раза. В каждом расчёте исключается одно семейство, остальные три получают равный вес.

Для каждого муниципалитета сохраняются:

* совпадение ведущего класса;
* число совпадений из четырёх;
* минимальный `margin`;
* диапазон энтропии;
* устойчивость направления D/G.

### 9.7. Проверка по опорным участникам

В каждом reference профиле выбирается верхняя четверть территорий по собственной полной raw affinity.

Минимальное число опорных участников равно двум.

Эта процедура является проверкой чувствительности к размытым границам и не является независимой валидацией.

## 10. Round18. Чувствительность к представлению признаков

Round18 использует ту же строгую панель и фиксирует `k`, правило рёбер, kernel, `omega`, `resolution` и seed.

Сравниваются три представления.

### 10.1. Reference

Шесть частей: пять опубликованных категорий и `Other`, затем CLR, плюс отдельный уровень `Total`.

### 10.2. R1

Используются только пять опубликованных категорий.

`Other` не строится.

После нормировки применяется CLR.

### 10.3. R2

Используются логарифмы пяти наблюдаемых уровней категорий.

Каждый уровень проходит устойчивое месячное масштабирование.

`Total` сохраняется отдельным блоком.

R2 может повторно включать часть информации об общем масштабе, поэтому он рассматривается именно как чувствительность представления, а не как замена reference.

Перед альтернативными расчётами reference gate требует точного воспроизведения базового графа и меток.

Результаты хранятся в `outputs/round18_representation/`.

## 11. Чувствительность к построению рёбер

Представление признаков фиксируется.

Проверяется:

```text
k in [10, 15, 20, 30, 50]
```

Для каждого `k` сравниваются:

* `mutual-kNN`;
* `union-kNN`.

В `union-kNN` ребро существует, если хотя бы один узел включает другой в список своих ближайших соседей.

Актуальная исправленная версия хранится в:

```text
outputs/final_competition_upgrade/edge_sensitivity_v3/
```

Предыдущая реализация сохранена для происхождения результатов, но не считается текущей, поскольку она теряла часть односторонних номинаций.

## 12. Round21. Чувствительность к временной связи

Канонические таблицы находятся в:

```text
outputs/round21_structural_sensitivity/
```

Реальная сетка:

```text
omega in [0,5; 1; 2; 4]
```

Внутримесячные графы не перестраиваются.

### 12.1. Метрики структуры

Используются:

* ARI;
* NMI;
* `fine-to-coarse micro purity`;
* `macro purity`;
* минимальный retention;
* pair retention;
* coarse pair precision;
* условные энтропии;
* variation of information.

Парные количества рассчитываются комбинаторно через `C(n,2)`. Объектные циклы порядка `N²` не используются.

Энтропии считаются с логарифмом по основанию 2.

### 12.2. Matched K контроль

Для `omega = 1` проверяется сетка:

```text
resolution = 0,50; 0,60; ...; 1,50
```

Выбор строки выполняется только по близости числа декабрьских сообществ к reference `K = 10`.

`resolution = 0,80` выбирается потому, что даёт `K = 10`.

ARI и NMI не участвуют в выборе строки.

### 12.3. Held out ось Atlas

`omega` не входит в четыре семейства, из которых собран Stability Atlas.

Поэтому изменение `omega` используется как дополнительная ось чувствительности.

Это не статистическая внешняя валидация, поскольку исходные данные остаются теми же.

## 13. Synthetic temporal benchmark v4

Синтетическая проверка используется для оценки временного сглаживания в ситуации, где истинные скрытые состояния известны.

Используются:

* 120 узлов;
* 12 месяцев;
* 4 истинных состояния;
* 20 независимых генераций на сценарий;
* 6 сценариев;
* `omega in [0; 0,25; 0,5; 1; 2; 4]`.

Основные ARI и NMI рассчитываются отдельно для каждого месяца, после чего агрегируются среднее, стандартное отклонение, минимум и медиана.

Это устраняет ошибку старого flattened подхода, который зависел от числового кодирования меток между месяцами.

`legacy_flattened_ari` и `legacy_flattened_nmi` сохранены только для исторической совместимости и не участвуют в выборе или сравнении `omega`.

Для метрик состояния и переходов выполняется помесячное сопоставление меток венгерским алгоритмом.

Для сценариев с реальными переходами описательная utility использует четыре компонента:

1. monthly ARI;
2. switch F1;
3. false switch rate;
4. абсолютную задержку.

Для сценариев без истинного перехода используются:

1. monthly ARI;
2. false switch rate.

Компоненты с отсутствующим значением не пропускаются молча.

Synthetic benchmark не выбирает новое `omega` для реальной модели.

## 14. ICVI v2

Код находится в [`../src/sbernet/icvi.py`](../src/sbernet/icvi.py).

ICVI v2 оценивает уже заданное разбиение и не используется для выбора `K`, representation, `k`, правила рёбер, алгоритма, `resolution` или `omega`.

Используются следующие показатели.

| Показатель | Пространство | Направление |
|---|---|---:|
| SW | признаки | больше лучше |
| CH | признаки | больше лучше |
| S_Dbw | признаки | меньше лучше |
| AVI | граф | больше лучше |
| AVU | граф | меньше лучше |
| ANUI | граф | больше лучше |
| MQ | граф | больше лучше |
| Q | граф | больше лучше |

### 14.1. SW

Средний евклидов коэффициент силуэта.

### 14.2. CH

Не нормированный индекс Калинского и Харабаша.

`CH/N` может использоваться только как дополнительная масштабная диагностика.

### 14.3. S_Dbw

Используется документированный вариант Halkidi и Vazirgiannis:

```text
S_Dbw = Scat + Dens_bw
```

Внутрикластерная дисперсия использует population standard deviation, `ddof=0`.

### 14.4. Матрица блоков графа

Строится симметричная матрица:

```text
S[i,j] = сумма весов рёбер между группами i и j
```

Внутреннее ребро дважды учитывается в `S[i,i]`.

### 14.5. AVI

```text
AVI_i = S[i,i] / sum_j S[i,j]
AVI = mean_i AVI_i
```

Для группы с нулевой силой вклад равен нулю.

### 14.6. AVU

```text
out_i = sum_j S[i,j] - S[i,i]
AVU_ij = S[i,j] / (out_i + in_j - S[i,j])
AVU = sum_i sum_j!=i AVU_ij / K
```

Нулевой знаменатель даёт ноль.

### 14.7. ANUI

```text
ANUI = 1 / (AVU + 1/AVI)
```

Если `AVI = 0`, ANUI равен нулю.

### 14.8. MQ

В v2 `MQ` означает TurboMQ.

```text
mu_i = S[i,i] / 2
epsilon_i = sum_j S[i,j] - S[i,i]
CF_i = mu_i / (mu_i + 0,5 × epsilon_i)
MQ = sum_i CF_i
```

TurboMQ не ограничен интервалом от 0 до 1.

### 14.9. Q

`Q` представляет собой взвешенную Newman Girvan modularity при `resolution = 1`.

Историческое поле `MQ` в старых таблицах содержало Newman Girvan `Q`. Эти таблицы не переписываются задним числом.

`MQ_per_K` используется только как описательная нормировка и не является отдельным конкурсным ICVI.

Полные определения приведены в [`ICVI.md`](ICVI.md).

## 15. Национальная внешняя валидация L1

Фиксированные A-G сопоставляются с независимой муниципальной статистикой Росстата.

Эти данные не участвуют в построении L1.

Используются:

* население;
* среднемесячная начисленная заработная плата работников организаций;
* общая занятость;
* отраслевая занятость по 15 компонентам ОКВЭД.

### 15.1. Покрытие

| Переменная | Число территорий |
|---|---:|
| подтверждённая линия происхождения | 1 903 |
| население | 1 903 |
| зарплата | 1 890 |
| занятость | 1 890 |
| отраслевая структура | 1 888 |

Линия происхождения строится через отдельно проверенное сопоставление муниципалитета и ОКТМО, а не через неограниченный fuzzy matching названий.

### 15.2. Скаляры

Для населения, зарплаты и занятости используется критерий Краскела и Уоллиса.

Вместе с p value рассчитывается `epsilon²`.

После общего теста выполняются попарные сравнения с коррекцией Бенджамини и Хохберга внутри соответствующего семейства.

### 15.3. Отраслевая композиция

15 отраслевых значений переводятся в доли.

Нули заменяются по правилу половины минимального положительного значения внутри строки, после чего строка повторно нормируется.

Затем применяется CLR.

Общее различие структуры проверяется перестановочным многомерным анализом с 999 перестановками.

### 15.4. Предсказание A-G по независимым данным

Используются:

* многоклассовая логистическая регрессия;
* Random Forest.

Перекрёстная проверка выполняется по пяти folds.

Импутация и масштабирование выполняются только внутри обучающего fold.

Основной показатель: macro F1.

Дополнительно публикуются balanced accuracy и accuracy.

Контрольный уровень строится через случайное перемешивание профильных меток.

## 16. Контроль регионального смешения

Внешняя выборка охватывает 73 региона.

### 16.1. Region held out GroupKFold

Целые регионы исключаются из обучения.

Один субъект Федерации не может одновременно находиться в обучающей и проверочной частях.

### 16.2. Внутрирегиональное центрирование

Для населения, зарплаты и занятости из значения муниципалитета вычитается медиана соответствующего региона.

После этого сравниваются уже внутрирегиональные отклонения.

Эти проверки уменьшают риск принять обычную региональную неоднородность за самостоятельный профиль спроса.

Они не доказывают причинную независимость от географии.

## 17. Round21. Скорректированная внешняя валидация

Для скалярных моделей используется 1 885 наблюдений и 73 региона.

Для sector CLR используется 1 883 наблюдения, 15 координат и 73 региона.

### 17.1. Reduced модель

Для зарплаты и занятости:


### 17.2. Full модель

Добавляются dummy профилей A-G.

A является reference категорией кодирования.

### 17.3. Partial R²

```text
partial R² =
(SSE_reduced - SSE_full) / SSE_reduced
```

### 17.4. Статистический вывод

Используются:

* совместный Wald тест с HC3;
* Freedman Lane перестановки остатков reduced модели;
* перестановки только внутри региона;
* 1 999 перестановок;
* seed `20261008`.

Для отраслевой композиции используется многомерный trace SS pseudo F с тем же ограничением перестановок по регионам.

Точные коэффициенты, HC3 p values, число exceedances, permutation summaries и bootstrap интервалы хранятся в CSV, а не только в основном тексте.

## 19. Round22. Точная реализация KEFRiNc

Round22 представляет собой отдельный benchmark другого класса алгоритмов атрибутированной сетевой кластеризации.

Он не заменяет L1 и не используется для выбора новой основной модели.

### 19.1. Входы

Используются:

* декабрьская reference матрица `X` размера `1 904 × 7`;
* сохранённый взвешенный граф `mutual-k20`.

Перед расчётом benchmark выполняется baseline gate.

### 19.2. Атрибутная часть

В варианте `Z` используется стандартизация с population standard deviation:

```text
ddof = 0
```

### 19.3. Сетевая часть

Для сетевой опции `M` один раз строится плотная матрица остатка:

```text
M_ij = P_ij - P_i+ × P_+j / P_++
```

Размер матрицы:

```text
1 904 × 1 904
```

Итерационные массивы расстояний остаются размера `N × K`.

### 19.4. Расстояние

Косинусное расстояние:

```text
d = 1 - cos
```

Обрезка применяется только для устранения погрешности вычислений с плавающей точкой.

Совместное расстояние:

```text
d_total = rho × d_X + xi × d_P
```

В канонической постановке:

```text
rho = 1
xi = 1
K = 9
```

### 19.5. Инициализация и seeds

Для каждого seed используется одна опубликованная random first / max sum инициализация.

Канонический seed равен 0.

Дополнительно выполняются seeds 0-9 для оценки оптимизационной устойчивости.

Seeds не ранжируются и не выбираются по ARI, ICVI или внешней статистике.

### 19.6. Условия ошибки

Расчёт считается неуспешным при:

* пустом кластере;
* нулевой норме строки или центра;
* нечисловом или бесконечном значении;
* `K != 9`;
* превышении 1 000 итераций, заданных YAML.

### 19.7. Метрики сравнения

ARI, NMI и VI не зависят от перестановки числовых меток.

Hungarian accuracy используется только как дополнительная one to one диагностика.

Pair retention:

```text
число пар, совместно кластеризованных в обоих разбиениях
/
число совместно кластеризованных пар reference
```

Pair precision:

```text
число пар, совместно кластеризованных в обоих разбиениях
/
число совместно кластеризованных пар KEFRiNc
```

Для Atlas сначала строится одно глобальное венгерское сопоставление с temporal December, затем расхождения стратифицируются по замороженным состояниям Atlas.

Пороговые значения и assignments Atlas при этом не меняются.

### 19.8. Происхождение реализации

Методологическая ссылка: DOI `10.3390/e24050626`.

Реализация выполнена independently clean room по описанию метода. Код внешнего upstream репозитория не использовался, поскольку его лицензия не была подтверждена как пригодная для повторного использования.

Артефакты находятся в:

```text
outputs/round22_kefrin_benchmark/
```

## 20. Round23. Точные экономические диагностики

Round23 использует строгую панель `1 904 × 24` и шесть положительных частей композиции.

Перед анализом выполняется свежий baseline gate.

Он заново строит месячные признаки и графы и требует точного:

```text
ARI = 1
NMI = 1
```

для трёх объектов:

1. полной supra модели;
2. temporal December;
3. static December.

Все endpoint определения, семейства множественных проверок, правила support, matching caliper и seeds фиксируются конфигурацией до расчёта.

Используются:

```text
4 999 перестановок
4 999 bootstrap повторов
seed = 20261009
```

### 20.1. Многомерная волатильность композиции

Для муниципалитета `i` используется:

```text
sqrt(
    mean(
        (DeltaCLR_itp - mean_t DeltaCLR_itp)^2
    )
)
```

Это скалярная мера общей временной изменчивости композиции.

### 20.2. Скорректированные тесты Atlas

Для Atlas state используются перестановки остатков reduced модели внутри замороженных A-G.

Это позволяет отделить связь с состоянием Atlas от части вариации, уже связанной с reference профилем.

### 20.3. Рост Marketplace

Для скорректированного коэффициента роста Marketplace используется HC3.

Проверка включает исходный `Total`, исходную долю Marketplace, профиль и регион согласно фиксированной спецификации Round23.

### 20.4. Matching

Муниципалитет не может повторно использоваться внутри одного comparison set.

Сопоставление cross profile и same profile строится по заранее заданным caliper и support правилам.

Расстояние корзин рассчитывается в композиционной геометрии через Aitchison distance.

### 20.5. Bootstrap профильной дисперсии

Муниципалитеты повторно выбираются с возвращением внутри замороженного профиля.

Для каждого bootstrap повтора заново рассчитываются:

* все 24 профильных средних;
* межпрофильная дисперсия;
* наклон Theil Sen.

Таким образом, неопределённость динамики не оценивается на одном фиксированном наборе профильных средних.

### 20.6. Географические аналоги

Используется направленная выборка `top 3` по сохранённому атрибуту ребра `distance`.

У 62 узлов имеется менее трёх графовых соседей.

Сохраняются два варианта:

1. directed selections;
2. unique pairs.

Географическое расстояние рассчитывается по representative points в `EPSG:4326` с помощью формулы haversine.

Эти пары являются ближайшими аналогами в замороженной L1 геометрии. Они не объявляются идентичными экономиками.

### 20.7. Артефакты

Первичные метрики муниципалитетов, пары, графики, manifest, freeze и контрольные суммы находятся в:

```text
outputs/round23_economic_mechanisms/
```

Round23 не меняет reference профили A-G и не повышает их научные статусы.

## 25. Краткое правило чтения результатов

Техническая логика проекта сводится к четырём различным вопросам.

1. Есть ли структура в данных спроса.
2. Насколько эта структура устойчива к изменению метода.
3. Связана ли она с независимыми социально-экономическими характеристиками.
4. Какие экономические интерпретации выдерживают дополнительные проверки.

Ни одна отдельная метрика не отвечает сразу на все четыре вопроса.

ARI и NMI измеряют сходство разбиений.

ICVI описывают свойства фиксированного разбиения.

Stability Atlas описывает локальную устойчивость и неопределённость.

Внешняя валидация проверяет экономическую содержательность.

Round22 проверяет чувствительность к другому классу алгоритмов.

Round23 проверяет конкретные экономические гипотезы на замороженных профилях.

Именно совместное чтение этих уровней определяет допустимую силу итоговых выводов.
